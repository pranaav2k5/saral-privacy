# Compliance traceability matrix

Maps each DPDP requirement to the feature that implements it and the tests that prove it. Rule numbers are as cited in the Feasibility Study and in `docs/PLAN.md` section 7. They must be verified against the Gazette text by the legal advisor before general availability. Update this file in the same pull request that changes a feature or a test.

| Rule (as cited) | Requirement | Feature | Test IDs | Status |
|---|---|---|---|---|
| Rule 3 | Standalone notice, itemized data and purposes, withdrawal link, English or Eighth Schedule language | Notice generator, vertical templates, versioned in-product publishing (`POST /v1/notices`, threat model 0010) | `packages/notice/src/*.test.ts` (43 tests), `apps/site/src/app/notice-generator/notice-form.test.tsx` (13 tests), review record `docs/compliance/notice-template-review.md` | engine and free page built; English and Hindi templates are drafts, legal review pending; in-product versioned notices not built |

| Rule 6(1)(e) and 8(3) | One-year minimum log retention | Audit log, lifecycle of at least 365 days | TC-RET-002 | in progress: canonical string v1 frozen (ADR 0002); hash chain, Merkle tree and anchors built and tested in `packages/audit-chain` (threat model 0001); database, verify and export endpoints, the nightly job (to a folder) and the standalone verifier built and tested (threat model 0001); the S3 Object Lock write, its retention lifecycle and the schedule are not built |
